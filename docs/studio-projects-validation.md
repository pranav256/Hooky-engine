Named projects — implementation and validation, 14 November 2026.

Studio saves complete editor snapshots as versioned JSON in the stable state directory, separate from job history and disposable media. Save project updates or renames the current project; Save as new creates a separate snapshot. Open project restores the source, topic, moments, selected clip, timing, caption edits and framing/subtitle choices without another model analysis. Saves use the existing atomic writer, and revisions reject stale updates from another tab. Browser-session edits stay separate from the saved project until an explicit save.

Validation:

- Full Python suite: 648 passed, 8 opt-in integration skips. New project checks cover restart/history independence, rename/copy, competing writers, stale revision rejection, failed disk writes preserving saved bytes, corrupt files, input bounds, invalid caption references, source credentials and authenticated access. A reused unauthenticated test client was corrected to use a fresh client. Existing process-tree tests retain their assertions with a longer startup wait for cold imports under machine load.
- Combined production browser CI passes at 390, 768, 1440 and 1728 pixels. The new `Hooky-website/scripts/check-studio-projects.mjs` uses real project API reads/writes against the runner's isolated Studio. It verifies separate browser sessions, selection/timing/styles/captions, independent copies, rename, stale-save recovery, browser draft restoration after history removal, failed restore/list/save recovery, unsaved-change confirmation, literal markup, keyboard focus and edited export payloads. Model, metadata and export-job requests use fixtures.
- Better Design UI/UX guidance, scoped source review, copy check and rendered DOM spacing review were run. Source and copy checks pass; final measured spacing has zero critical, serious or moderate findings. Desktop and mobile screenshots were inspected and the panel heading/spacing corrected. This is a scoped editor review, not a dashboard receipt or screen-reader certification.
- Engine distributions build and pass Twine/wheel-content checks; the wheel's named-project module and Studio assets match the working source and contain no saved projects or credentials. The production website build passes.

Limits: projects contain text and source URLs, and do not back up media. A source must remain available for export; a changed caption track can invalidate old edit timestamps. Saves are explicit and there is no cloud sync, deletion UI, batch export or media copying. Reload Studio to see projects saved from another browser. One Studio server process is supported; concurrent tabs are protected, but multi-worker deployments require an interprocess write lock. Each snapshot is bounded to 1 MiB, 100 moments and 200 caption phrases per moment. Live model/YouTube calls, screen-reader use and GPU rendering were not exercised.
